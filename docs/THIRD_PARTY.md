# Dependency provenance and licenses

All engine/SDL/Jolt source needed for an offline code build is bundled; OS/toolchain development prerequisites must be installed first. No prebuilt program, library or Gradle wrapper JAR is shipped. No proprietary game assets or original SOL 101 code are included. Engine decoder fixtures are generated by `tests/generate_fixtures.py` using the Python standard library. Their PNG/HDR/WAV/glTF input data lives in `tests/fixtures` and is independent of game assets. The optional `examples/showcase` has its own LICENSE.txt, asset-authoring tools and docs/CREDITS.md; none are engine library dependencies. Its enabled installation includes all asset/font notices under share/jsd-game-engine/showcase.

## Backend choices

The portable rendering target is desktop OpenGL 3.3, with a GL4 terrain tessellation path. Current vendor rendering technologies require additional backends/integration; consulting their documentation does not constitute bundling or implementing their SDKs. Useful primary references for future work include [Vulkan ray tracing](https://docs.vulkan.org/guide/latest/extensions/ray_tracing.html), [AMD FidelityFX SDK](https://gpuopen.com/fidelityfx-sdk/), [Jolt documentation](https://jrouwe.github.io/JoltPhysics/) and [glTF specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html).

The SDL and Jolt Android Gradle wrapper JARs were omitted because this is a source-only Linux distribution. Their Linux C/C++ sources are retained. System build tools, GPU/window/audio drivers and glibc are supplied by the host OS.

The bundled SDL tree also omits Windows Direct3D and Apple Metal renderer folders containing precompiled shader blobs. They are unused by the Linux build; retained Linux C/C++ source is unmodified, and the sdl2.pc.in build template is made relocatable. Exact changes are recorded in third_party/SDL2/SOURCE.json.
